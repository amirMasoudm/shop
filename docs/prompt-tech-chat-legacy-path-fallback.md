# تسکِ چت الف — فالبکِ ۴۰۴: آدرس‌های وردپرسی را خودکار نجات بده

این از دادهٔ واقعیِ سرچ کنسول درآمد، نه از حدس. **بیش از صد آدرسِ ایندکس‌شده** را با
یک قاعده برمی‌گرداند، بدونِ اینکه ردیفی به جدولِ ریدایرکت اضافه شود.

> **قواعدِ همیشگی:** با pathspec صریح کامیت کن، CHANGELOG را ننویس (کارِ مدیر است)،
> و هیچ رشتهٔ مخصوصِ داده‌نما را در کدِ core هاردکد نکن.

---

## چرا — دو یافتهٔ سرچ کنسول

### یک — ۲۷۹ آدرسِ وردپرسی هنوز در ایندکسِ گوگل‌اند

از ۴۳۳ صفحهٔ ایندکس‌شده، فقط **۱۵۴** آدرسِ اپِ ماست. بقیه آدرس‌های سایتِ قدیمی‌اند
که گوگل هنوز نگهشان داشته. ما فقط ۴۹ ریدایرکت داریم؛ بقیه وقتی دوباره خزیده شوند
**۴۰۴** می‌گیرند و می‌افتند.

### دو — الگویی که همه را حل می‌کند

ایمپورتِ وردپرس **اسلاگِ وردپرس را عیناً نگه داشته**. پس آدرسِ قدیمی دقیقاً همان
اسلاگِ مقالهٔ امروزِ ماست، فقط بدونِ پیشوندِ `‎/blog/`:

```
/فناوری-plc-power-line-carrier/   ->  /blog/فناوری-plc-power-line-carrier    200
/xpic-و-صرفه-جویی-در-منابع-فرکانسی/ -> /blog/xpic-و-صرفه-جویی-در-منابع-فرکانسی 200
/mtctce-06-97/                    ->  /blog/mtctce-06-97                     200
/keyloggers/                      ->  /blog/keyloggers                       200
```

**۱۶ از ۱۶ نمونه‌ای که تست شد، همین‌طور بود.** سیزده‌تایشان امروز ۴۰۴ می‌دهند.

---

## کار — یک فالبک، سه قاعده

جایی که **همه‌چیزِ دیگر شکست خورده** و قرار است ۴۰۴ برگردد، پیش از ۴۰۴ این سه را
امتحان کن. فقط برای `GET` و `HEAD`.

### قاعدهٔ ۱ — اسلشِ پایانی

```
/shop/   -> 404      (emruz)
/blog/   -> 404
/about/  -> 404
```

این تلهٔ Spring Boot 3 است: تطبیقِ اسلشِ پایانی پیش‌فرض خاموش شد. سایتِ وردپرسی
همه‌جا اسلشِ پایانی داشت، پس هر بک‌لینک و بوکمارکِ قدیمی الان می‌شکند.

اگر مسیر با `/` تمام می‌شود و نسخهٔ بدونِ اسلش **resolve می‌شود** → `301` به آن.

⚠️ **در nginx حلش نکن.** آنجا یک `rewrite` کلی، هر ۴۹ ریدایرکتِ وردپرسی را
**دوپرشی** می‌کند (چون `normalize()` خودش اسلش را برمی‌دارد). در اپ حل شود.

### قاعدهٔ ۲ — مسیرِ تک‌بخشی که اسلاگِ یک مقاله است

`‎/{x}` که `{x}` اسلاگِ یک مقالهٔ منتشرشده است → `301` به `‎/blog/{x}`.

🔴 **ولی حتماً به مقصدِ نهایی، نه به `‎/blog/{x}`.** اسلاگِ خیلی از مقاله‌ها را همین
هفته عوض کرده‌ایم. مثلاً:

```
/mtctce-06-97/  ->  /blog/mtctce-06-97  ->  /blog/دوره-mtctce-شهریور-97     2 paresh ✗
/mtctce-06-97/  ->  /blog/دوره-mtctce-شهریور-97                            1 paresh ✓
```

پس پیش از ریدایرکت، زنجیرهٔ `LegacyRedirect` را هم دنبال کن و **یک‌باره** به مقصدِ
زنده برو.

### قاعدهٔ ۳ — `‎/product/{x}`

اگر محصولی با آن اسلاگ resolve شود → `301` به آدرسِ هیبریدِ کاملش.

⚠️ فقط حدودِ **۴۰٪** جواب می‌دهد (۳ از ۸ نمونه) چون اسلاگِ خیلی از محصولات حین
کارِ داده عوض شده. بقیه ۴۰۴ می‌مانند و اشکالی ندارد.

---

## 🔴 پنج گاردی که نبودشان فاجعه است

**یک — فقط روی ۴۰۴.** این فالبک هرگز نباید جلوی مسیرِ واقعی را بگیرد. اگر کنترلری
جواب می‌دهد، دست نزن.

**دو — مسیرهای رزرو را رد کن:** `‎/api/`، `‎/l/`، `‎/Admin.html`، `‎/AdminLogin.html`،
`‎/uploads/`، فایل‌های استاتیک (`.css`, `.js`, `.png`, `.ico`, …)، `robots.txt`،
`sitemap.xml`.

**سه — حلقه نساز.** اگر مقصدِ محاسبه‌شده با خودِ مسیرِ ورودی یکی شد، ریدایرکت نکن؛
۴۰۴ بده.

**چهار — یک پرش، نه بیشتر.** با `curl -w '%{num_redirects}'` ثابت کن.

**پنج — ۴۰۴ واقعی باید ۴۰۴ بماند.** مسیرِ بی‌معنا نباید به جایی ریدایرکت شود.
چارچوبِ سئوی ما «هرگز ۴۰۴» را فقط برای محصولِ حذف‌شده گفته، نه برای هر آشغالی.

---

## لاگ

هر ریدایرکتی که این فالبک می‌زند، یک خطِ لاگ بزند (مسیرِ ورودی → مقصد → کدام
قاعده). اینکه بعداً بفهمیم چند آدرس نجات پیدا کرد، فقط از همین‌جا ممکن است.

---

## معیارِ پذیرش

با `curl -sL -w '%{http_code}|%{num_redirects}'` روی سایتِ زنده:

- [ ] `‎/shop/` و `‎/blog/` و `‎/about/` → `200` با **یک** پرش.
- [ ] `‎/keyloggers/` و `‎/linux-essay/` و `‎/روش-کدگذاری-هافمن/` → `200` با **یک** پرش
      به `‎/blog/…`.
- [ ] 🔴 `‎/mtctce-06-97/` → `200` با **یک** پرش، مستقیم به `‎/blog/دوره-mtctce-شهریور-97`
      (نه دو پرش).
- [ ] `‎/product/qrt-5/` → `200` با یک پرش به آدرسِ هیبریدِ محصول.
- [ ] `‎/api/v1/legacy-redirects` همچنان `401/403` بدهد، نه ریدایرکت.
- [ ] `‎/l/{code}` رفتارِ فعلی‌اش را حفظ کند.
- [ ] `‎/robots.txt` و `‎/sitemap.xml` دست‌نخورده.
- [ ] یک مسیرِ کاملاً بی‌معنا (`‎/in-adres-vojud-nadarad/`) → **۴۰۴ واقعی**.
- [ ] هر ۴۹ مسیرِ وردپرسیِ موجود همچنان **یک‌پرشی** بمانند (رگرسیون).
- [ ] `activity_logs` دست‌نخورده.
