# تصمیمِ سیستمِ طراحی — «الف۲ / کنتراست»

**تاریخ:** ۱۶ شهریور ۱۴۰۵ (۲۰۲۶-۰۹-۰۷) · **تصمیم‌گیرنده:** مالک · **وضعیت:** تأییدشده، پیاده‌سازی عقب‌افتاده

بومِ طراحی: <https://claude.ai/code/artifact/b0f8c2c4-24cb-46a4-b90d-61868ab4dff7>
فایل‌های کاری: `design/unify/*.dc.html`

> ⏸ **پیاده‌سازی به‌خواستهٔ مالک چند روز عقب افتاد.** تا اعلامِ بعدیِ او هیچ قالبی عوض
> نمی‌شود. این سند برای همان موقع نوشته شده تا دوباره از صفر بحث نکنیم.

---

## چرا این کار لازم شد

مالک: «همهٔ صفحه‌ها باید یک طراحیِ یک‌دست با همین رنگ‌بندیِ فروشگاه داشته باشند… رفتارهای
کنشی خیلی نرم بشوند، الان گاهی خیلی خشک است، خصوصاً موبایل».

هر دو شکایت با گرپ روی خودِ کد اندازه‌گیری شد — این اعداد پایهٔ تصمیم‌اند:

**واگراییِ توکن‌ها.** از شش قالب، فقط **دو** توکن همه‌جا یکی است (`--primary: #1b4f8a` و
`--accent: #e8861a`). بقیه واگرا شده‌اند:

| توکن | مقادیرِ متفاوت | نمونه |
|---|---|---|
| شعاع | **۴** | ۱۲px فروشگاه · ۲۲px خانه · ۱۶px وایمکس · ۱۸px پنل |
| خاکستریِ متن | **۴** | `#8c9cb5` · `#6b7280` · `#64748b` |
| رنگِ متن | **۲** | `#1a2235` · `#1f2937` |
| پس‌زمینه | **۲** | `#f2f5fb` · `#f6f8fb` |
| خط | **۳** | `#e0e8f2` · `#dbe5f2` · `#e5e7eb` |

نامِ توکن‌ها هم یکسان نیست: `--text-muted` / `--mid` / `--text-gray` همگی یک نقش دارند.

**خشکیِ حرکت.** ریشه‌اش این است:

- **۲۴** اعلانِ `transition` متمایز در پنج قالب، ولی فقط **یک** `cubic-bezier` در کلِ پروژه؛
  باقی `ease`ی خام‌اند.
- **۳۲** قاعدهٔ `:hover` در برابرِ تنها **۱** قاعدهٔ `:active`. روی موبایل hover معنا ندارد،
  پس لمس هیچ بازخوردی نمی‌دهد.
- **صفر** مورد `@media (hover: hover)` در کلِ پروژه — برای همین روی موبایل استایلِ hover بعد
  از لمس **می‌چسبد و نمی‌رود**. این دقیقاً همان «خشکیِ موبایل» است.
- `:focus-visible` فقط در `home.html` هست (۳ مورد)؛ چهار قالبِ دیگر صفر.

## جهتِ تأییدشده

بعد از دو دورِ بررسی (اول سه جهتِ گِرد/بازفاصله که مالک رد کرد؛ بعد سه جهتِ خط‌کشی‌شده)،
جهتِ **الف۲ — کنتراست** انتخاب شد. خواستهٔ صریحِ مالک: «خط‌کشی‌شده و شیک، نه خمیده؛
المان‌ها به هم نزدیک، فضای خالیِ کمتر، ولی نه گیج‌کننده» و «روحِ مدرن».

**آنچه سیستم را می‌سازد:**

1. **شبکه با مرزِ مشترک.** سلول‌ها فاصله ندارند؛ مرزشان یکی است (`gap: 1px` روی گریدی که
   پس‌زمینه‌اش رنگِ خط است). این هم چگالی می‌دهد هم نظم.
2. **شعاع صفر.** هیچ گوشهٔ گِردی، هیچ قرصی.
3. **بدونِ سایه.** ساختار از خط می‌آید نه از ارتفاع.
4. **یک بلوکِ تیره سرِ صفحه.** هویت و تیتر رویش می‌نشینند و صفحه را لنگر می‌اندازد؛
   داده روی سفید می‌ماند. مرزِ تیره و روشن خودش یک خطِ طراحی است.
5. **کنتراستِ تایپ.** لیبلِ ۱۰px مونوی بزرگ‌فاصلهٔ حروف در برابرِ تیترِ ~۲۳px با تراکینگِ
   منفی. مدرن‌بودن از همین تضاد می‌آید، نه از گِردکردن.
6. **عددها مونو و هم‌عرض.** قیمت و کدِ کالا با `JetBrains Mono` و
   `font-variant-numeric: tabular-nums` تا زیرِ هم بنشینند.
7. **نارنجی فقط نشانگر است.** زیرِ تبِ فعال و روی وضعیتِ «در راه». هیچ‌جای دیگر.

### توکن‌های نهایی

```css
/* tokens.css — یک منبع برای هر شش صفحه */
:root {
  /* رنگ — پالت دست‌نخورده می‌ماند */
  --primary:   #1b4f8a;
  --primary-lt:#2563ad;
  --accent:    #e8861a;

  --ink:       #0b1119;   /* متنِ اصلی */
  --ink-2:     #46536b;   /* متنِ میانی */
  --ink-3:     #94a2b8;   /* متنِ کم‌رنگ */

  --dark:      #101826;   /* بلوکِ تیرهٔ سرِ صفحه */
  --on-dark:   #8fa3c0;   /* متنِ روی تیره */

  --surface:   #ffffff;
  --line:      #e9edf2;   /* خطِ جداکننده */
  --line-2:    #f2f5f8;   /* خطِ داخلی، نرم‌تر */

  /* شکل */
  --radius: 0;

  /* حرکت */
  --dur:  140ms;
  --ease: cubic-bezier(.2, .8, .3, 1);

  /* فاصله — پلهٔ فشرده و منظم */
  --s1: 6px;  --s2: 10px;  --s3: 14px;  --s4: 18px;

  /* ارتفاعِ کنترل */
  --ctl-h: 36px;          /* موبایل: 44px */
}
```

فونت: `Vazirmatn` برای متن + `JetBrains Mono` برای عدد و کد (هر دو از Google Fonts).

## چهار قاعدهٔ حرکت

مستقل از ظاهرند و روی همهٔ صفحه‌ها یکسان اعمال می‌شوند. این‌ها همان چیزی‌اند که
«خشکیِ اکت‌ها» را حل می‌کنند:

1. **یک منحنیِ واحد.** همهٔ ترنزیشن‌ها `var(--dur) var(--ease)`. هیچ `ease`ی خام،
   هیچ عددِ سرخود.
2. **بازخوردِ فشردن.** هر عنصرِ کلیک‌شدنی `:active` دارد — در این سیستم **تغییرِ رنگِ
   پس‌زمینه**، نه `scale` (چون گوشه‌ها تیزند و مقیاس در شبکهٔ هم‌مرز بد می‌افتد).
3. **گاردِ لمس.** هر قاعدهٔ `:hover` داخلِ
   `@media (hover: hover) and (pointer: fine)` برود، وگرنه روی موبایل می‌چسبد.
4. **هدفِ لمس ۴۴ پیکسل** روی موبایل، و `:focus-visible` روی همهٔ کنترل‌ها.

به‌علاوه: `@media (prefers-reduced-motion: reduce)` روی همهٔ صفحه‌ها (الان فقط در دو
قالب هست).

## نقشهٔ اجرا — وقتی مالک اجازه داد

**اول `tokens.css` ساخته شود** و در `<head>` همهٔ قالب‌ها لینک شود؛ بعد صفحه‌به‌صفحه
مقادیرِ محلی با `var(--…)` جایگزین شوند. **همهٔ شش صفحه با هم نه** — ریسکش زیاد است.

ترتیبِ پیشنهادی، از کم‌ریسک به پرریسک:

| # | صفحه | چرا این ترتیب |
|---|---|---|
| ۱ | `blog.html` | کم‌ترین CSS (۱ ترنزیشن، ۱ hover) — میدانِ تمرینِ بی‌خطر |
| ۲ | `learn.html` | ساده، و آرشیوِ تصویری‌اش تستِ خوبی برای شبکه است |
| ۳ | `wimaxnear.html` | تازه بازسازی شده، ساختارش تمیز است |
| ۴ | `home.html` | شعاعِ ۲۲ → ۰ بیشترین تغییرِ دیداری را دارد |
| ۵ | `CL.html` (فروشگاه) | بزرگ‌ترین و پرترافیک‌ترین — بعد از پختنِ سیستم |
| ۶ | `customerPanel.html` | آخر، چون پشتِ لاگین است و کم‌تر دیده می‌شود |

⚠️ `Admin.html` و `SalesPanel.html` عمداً در این فهرست نیستند — ابزارِ داخلی‌اند و
اولویتشان با صفحه‌های عمومی فرق دارد؛ جداگانه تصمیم گرفته شود.

## جهت‌هایی که کنار گذاشته شدند

روی صفحهٔ دومِ بوم نگه داشته شده‌اند تا اگر بحث برگشت از صفر شروع نکنیم:

- **الف۱ — خنثی:** همان شبکه بدونِ بلوکِ تیره. آرام‌ترین و کم‌ریسک‌ترین.
- **الف۳ — نمایه:** بی‌رنگ‌ترین؛ شمارهٔ نمایه روی هر سلول و خط‌کشِ مدرج زیرِ تیتر.
- **دورِ اول (گِرد/بازفاصله):** سه جهت با شعاعِ ۱۴ تا ۲۰ و سایه، که مالک هر سه را رد کرد.
  درسش ثبت شود: خواستهٔ او **خط‌کشی‌شده و فشرده** است، نه نرم و بازفاصله.
