به این چت به‌عنوان «چت توسعه‌ی فنی» پروژه‌ی فروشگاه داده نما نگاه کن. یک چت مدیر جدا معماری و سئو را کنترل می‌کند و این تسک را به تو سپرده.

## زمینه (بخوان قبل از شروع)
- پروژه: Spring Boot 3.5.6 / Java 17 / MongoDB. فروشگاه تجهیزات شبکه (تمرکز میکروتیک/وایرلس).
- برنچ کاری: `security-hardening`. دیپلوی تست: `mvn clean package -DskipTests` سپس `docker compose up -d --build` (mongo/nginx/backend با docker-compose بالا می‌آیند؛ صفحه‌ی اصلی روی http://localhost/).
- فایل‌های مرجع را حتماً اول بخوان: `docs/CHANGELOG.md` و `docs/marketing-seo-roadmap.md`.
- ⚠️ قانون طلایی: این پروژه SSR+SPA است و سئو «غیرقابل‌خطا»؛ هیچ تغییری نباید رندر سروری صفحات عمومی، متاتگ‌ها یا اسکیماها را بشکند. صفحات عمومی: `/`, `/product/{slug}`, `/category/{slug}`, `/blog*`.

## تسک ۱ — رفع حفره‌ی امنیتی نوشتن محصول (اولویت: بحرانی)
در `SecurityConfig.java`، مسیر `/api/v1/products/**` زیر `permitAll` است؛ یعنی endpointهای نوشتن محصول عمومی‌اند و هر کسی می‌تواند محصول بسازد/ویرایش/حذف کند.
**باید:** فقط متدهای **خواندن** (GET) روی `/api/v1/products/**` عمومی بماند، ولی **POST/PUT/DELETE** فقط `ROLE_ADMIN`.
- الگوی درست (مهم): matcherهای اختصاصی‌تر باید *قبل از* permitAll عمومی بیایند — دقیقاً مثل کاری که برای `/api/v1/articles/admin/**` قبلِ `/api/v1/articles/**` انجام شده (به همان فایل نگاه کن).
- راه پیشنهادی: `.requestMatchers(HttpMethod.POST, "/api/v1/products/**").hasRole("ADMIN")` و همین‌طور PUT و DELETE، قبل از خط permitAll محصولات.
- مراقب باش: مسیر عمومی `POST /api/v1/products/search` (جستجوی محصولات فرانت) نباید ادمین‌شود — این استثناست و باید permitAll بماند. پس یا این را جداگانه قبل از قانون POST/ADMIN به permitAll اضافه کن، یا قانون ADMIN را دقیق‌تر بنویس.
- تست بعد از تغییر: بدون لاگین `POST /api/v1/products` باید 401/403 بدهد؛ `POST /api/v1/products/search` و همه‌ی GETها باید همچنان کار کنند؛ فروشگاه (`/`) و صفحه‌ی محصول سالم بمانند.

## تسک ۲ — بهینه‌سازی تصاویر و Core Web Vitals سبک (اولویت: متوسط)
- به همه‌ی `<img>`های محصول/کارت که `loading` ندارند `loading="lazy"` بده (به‌جز تصویر اصلی صفحه‌ی محصول که باید eager بماند).
- به تصاویر بزرگ `decoding="async"` اضافه کن.
- در بلوک‌های SSR (`#ssr-product`, `#ssr-category`, صفحات blog/article) مطمئن شو تصاویر `width`/`height` یا `aspect-ratio` دارند تا CLS ایجاد نشود.
- دست به منطق SPA/واکشی نزن؛ فقط ویژگی‌های تصویر.

## معیار پذیرش
- کامپایل و بیلد موفق؛ استک با docker بالا بیاید.
- تست‌های امنیتی بالا پاس شوند (با curl یا مرورگر داخلی نشان بده).
- هیچ رگرسیونی در رندر SSR صفحات عمومی (با `curl -s http://localhost/product/<یک‌اسلاگ>` چک کن که متا/اسکیما سرجایشان است).
- در انتها: خلاصه‌ی تغییرات + نتایج تست را گزارش بده تا من (کاربر) به چت مدیر منتقل کنم و `CHANGELOG.md` به‌روز شود. اگر فیلد دیتابیسی اضافه/عوض کردی، صریح بگو.

بعد از اتمام، commit با پیام فارسی گویا بزن (برنچ همین `security-hardening`).
