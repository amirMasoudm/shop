# پرامپتِ چت الف — پیاده‌سازیِ Torob Product API v3

## زمینه و تغییرِ تصمیم
تسکِ قدیمیِ «فیدِ ترب» (`docs/prompt-tech-chat-task8-torob-feed.md`) درست بلاک شده بود چون فرمتِ رسمی در دست نبود. **حالا مستنداتِ رسمی خوانده شد** (github.com/Torob/Torob-Sync) و معلوم شد فرضِ آن تسک (ساختِ فیدِ XML مثلِ Google Merchant) **کلاً غلط بود**: ترب فید نمی‌خواند — **خودش با JWT به یک اندپوینتِ POST رویِ سایتِ ما ریکوئست می‌زند**. آن فایل منسوخ است؛ این پرامپت جایگزینش است.

راهنمایِ ترب می‌گوید پیاده‌سازیِ API «فقط برایِ فروشگاه‌هایِ بزرگ و فروشگاه‌سازها توصیه می‌شود» و فروشگاه‌هایِ کوچک/متوسط با خزندهٔ خودکار هم کار می‌کنند — **کاربر آگاهانه تصمیم گرفت API پیاده شود** (همگام‌سازیِ سریع‌تر و دقیق‌ترِ قیمت/موجودی، بدونِ اتکا به تفسیرِ خزنده).

## ⚠️ ترتیبِ فعال‌سازی (کد را کامل بنویس، ولی فعال‌شدنش خودکار نیست)
1. **`aud` توکن باید با hostnameِ APIِ ما یکی باشد** و ترب باید بتواند به دامنه ریکوئست بزند. الان سایت فقط با IP و رویِ HTTP بالاست و `dadehnama.com` هنوز به وردپرسِ قدیم اشاره می‌کند. طبقِ تصمیمِ ۱۶ اوت (در `INFRA-CHANGELOG.md`) ترتیبِ لازم: **ریدایرکتِ ۳۰۱ → TLS → سوییچِ DNS**.
2. **سوییچِ DNS کافی نیست** — این‌ها هم لازم‌اند و خودکار نمی‌شوند: دیپلویِ همین کد، **ثبت‌نامِ فروشگاه در پنلِ ترب + تیکت به پشتیبانی** (ترب خودش اندپوینتِ ما را کشف نمی‌کند؛ باید آدرس را بدهیم و تست هماهنگ شود)، و TLS.
3. 🪤 **تلهٔ nginx — مهم:** چکِ `aud` را از هدرِ `Host` می‌خوانیم، ولی nginx جلویِ اپ است. اگر `proxy_set_header Host $host;` درست ست نشده باشد، اپ hostname را `localhost` می‌بیند و **اعتبارسنجیِ `aud` همیشه fail می‌کند** (۴۰۱ برایِ همهٔ ریکوئست‌هایِ سالمِ ترب). کانفیگِ nginx را همین حالا چک کن؛ اگر لازم بود از چت ج بخواه اصلاح کند.
4. **سابقهٔ ترب رویِ سایتِ قدیم:** طبقِ سندِ منسوخِ تسکِ ۸، سایتِ وردپرسیِ قبلی به ترب وصل بود — یعنی احتمالاً حسابِ ترب با آدرس‌هایِ قدیمی وجود دارد. موقعِ هماهنگی با پشتیبانیِ ترب این را مطرح کنیم تا لیستِ قدیمی به API سوییچ شود، نه اینکه دو منبعِ موازی بمانند.

## ✅ واحدِ قیمت — حل شد
`current_price` باید **عددِ صحیح به تومان** باشد. واحدِ فایلِ داخلیِ شرکت تأیید شد: **ستونِ D به هزار تومان است** → قیمتِ نمایشِ مشتری `= D × 1000 × 1.08`. چت ب این را روی دیتابیس درست اعمال کرده، پس `onlinePrice` از قبل تومانِ درست است و **این API فقط باید همان مقدار را به `int` تبدیل کند** — هیچ ضرب/تقسیمِ اضافه‌ای در لایهٔ ترب نزن.

## اندپوینت
- مسیر: `POST /torob_api/v3/products` (مسیر را خودمان انتخاب می‌کنیم؛ همین را بگذار).
- `Content-Type: application/json`.
- در `SecurityConfig` باید `permitAll()` شود (احرازِ هویتش از طریقِ JWTِ خودِ ترب انجام می‌شود، نه سشنِ ما). دقت: قاعدهٔ `anyRequest().authenticated()` وگرنه بلاکش می‌کند — همان کلاسِ باگی که در `/img/**` دیدیم.

### سه حالتِ بدنهٔ درخواست (هر سه الزامی)
1. `{"page": <int>, "sort": "<date_added_desc|date_updated_desc>"}`
2. `{"page_urls": ["<absolute url>", ...]}`
3. `{"page_uniques": ["<id>", ...]}`

**قاعدهٔ صریحِ مستندات:** هیچ مقدارِ پیش‌فرضی برایِ پارامترها نگذار. بدنهٔ خالی یا پارامترِ نامعتبر → **۴۰۰**.

### صفحه‌بندی
- صفحه‌ها **از ۱** شروع می‌شوند (نه صفر — برخلافِ بقیهٔ APIهایِ پروژه، حواست باشد).
- هر صفحه **دقیقاً ۱۰۰ محصول**، جز صفحهٔ آخر.
- `sort=date_added_desc` برایِ همهٔ فروشگاه‌ها الزامی است؛ `date_updated_desc` برایِ فروشگاه‌سازها. **هر دو را پیاده کن** — فیلدِ `updatedAt` را داریم و کارِ اضافه‌ای نیست (فقط برایِ رکوردهایی که `updatedAt` نال است fallback به `createdAt` بگذار وگرنه سورت می‌شکند).

## احرازِ هویت JWT (بدونِ نیاز به کتابخانهٔ جدید)
هدرها: `X-Torob-Token` (توکن) و `X-Torob-Token-Version: 1`.
- الگوریتم: **EdDSA (ed25519)**. کلیدِ عمومیِ ترب (از مستنداتِ رسمی):
  `MCowBQYDK2VwAyEAt6Mu4T0pBORY11W+QeM35UsmLO3vsf+6yKpFDEImFk0=`
  این یک **کلیدِ عمومی** است، رمز نیست — می‌تواند در کد/کانفیگ باشد. ترجیحاً در `application.properties` بگذار تا اگر ترب چرخاندش نیازی به ری‌بیلد نباشد.
- **Java 17 داریم و JCA از Java 15 به بعد `Ed25519` را بومی دارد** — هیچ dependencyِ جدیدی (jjwt/BouncyCastle) لازم نیست. توکن را دستی بشکن (سه بخشِ base64url)، امضا را با `Signature.getInstance("Ed25519")` روی `header.payload` بررسی کن، و claimها را با Jackson (از قبل موجود) بخوان.
- چهار اعتبارسنجیِ الزامی: (۱) صحتِ امضا، (۲) `exp` نگذشته باشد، (۳) `nbf` رسیده باشد، (۴) **`aud` دقیقاً با hostnameِ APIِ ما (از هدرِ `Host`) یکی باشد** — این یکی از نظرِ امنیتی حیاتی است، ردش نکن.
- هر شکستِ اعتبارسنجی → **۴۰۱** (مستندات فرمتِ خطا را تعیین نکرده؛ ساده و بدونِ افشایِ جزئیات).

## پاسخ
```json
{
  "api_version": "torob_api_v3",
  "current_page": <int>,
  "total": <int>,
  "max_pages": <int>,
  "products": [ ... ]
}
```

### نگاشتِ فیلدهایِ محصول (از `Product` ما → ترب)
| فیلدِ ترب | الزامی | منبع در پروژه | نکته |
|---|---|---|---|
| `page_unique` | ✅ | `Product.id` | **باید همیشه ثابت بماند** (حداکثر ۲۰۰ کاراکتر). `id` بهترین گزینه است، نه اسلاگ (اسلاگ ممکن است تغییر کند). |
| `page_url` | ✅ | `hybridPathEncoded(p)` در `StoreWebController` + baseUrl | **باید مطلق باشد** (حداکثر ۱۵۰۰). از همان تابعِ موجود استفاده کن تا با canonicalِ ما یکی باشد — نه ساختِ URLِ موازی. |
| `title` | ✅ | `name` | حداکثر ۵۰۰ — truncate کن. |
| `subtitle` | ➖ | `seoTitle` یا خالی | حداکثر ۵۰۰. |
| `current_price` | ✅ | `onlinePrice` → `int` تومان | **هرگز null نشود.** ⚠️ به بخشِ «واحدِ قیمت» بالا نگاه کن. |
| `old_price` | ➖ | `price` (اگر بزرگ‌تر از onlinePrice بود) | فقط وقتی واقعاً تخفیف هست. |
| `availability` | ✅ | `stock != null && stock > 0` | boolean. |
| `category_name` | ➖ | نامِ دستهٔ متناظرِ `categoryId` | حداکثر ۲۰۰. |
| `image_links` | ✅ | `images` با baseUrlِ مطلق | اولی = تصویرِ اصلی، هرکدام حداکثر ۱۰۰۰ کاراکتر. مستندات: زیرِ ۶۰۰×۶۰۰ نمایش داده نمی‌شود، ۹۰۰×۹۰۰+ توصیه شده — عکس‌هایِ ما تا ۲۰۰۰px نگه داشته می‌شوند پس مشکلی نیست، ولی محصولی که عکس ندارد را چک کن (آرایهٔ خالی نفرست اگر الزامی است؛ محصولِ بی‌عکس را کنار بگذار و در لاگ بشمار). |
| `short_desc` | ➖ | `seoDescription` یا ابتدایِ `description` | حداکثر ۵۰۰، **متنِ خالص** (اگر `description` جایی HTML دارد پاکسازی شود). |
| `spec` | ✅ | `specifications` (`Map<String,String>`) | دقیقاً dict می‌خواهد؛ اگر خالی بود **`{}` بفرست، نه null**. (`techSpecs` جداست و ساختارش لیستی است — از `specifications` استفاده کن.) |
| `guarantee` | ➖ | ثابت (مثلاً «ضمانتِ اصالتِ کالا») | حداکثر ۲۰۰. با مالک هم‌خوان باشد — ادعایِ گارانتیِ بی‌پشتوانه نکن. |
| `date_added` | ✅ | `createdAt` | ISO 8601 **با تایم‌زون** (`Instant.toString()` → `...Z` مناسب است). |
| `date_updated` | ➖/✅ | `updatedAt` (fallback: `createdAt`) | چون `date_updated_desc` را پیاده می‌کنیم، **الزامی می‌شود**. |
| `seller_name` / `seller_city` | ➖ | **نفرست** | مالِ مارکت‌پلیس‌هاست، ما نیستیم. |

### دو تصمیمِ محتواییِ لازم (طبقِ قوانینِ پروژه)
- **محصولاتِ بدونِ قیمتِ واقعی را از خروجی حذف کن.** قانونِ ۱۲ پروژه «قیمتِ صفر» را پرچم می‌داند. مستنداتِ ترب می‌گوید `current_price: 0` به‌همراهِ `availability: true` یعنی **کالایِ رایگان** — یعنی اگر محصولِ بی‌قیمت را بفرستیم، ترب آن را «رایگان» فهرست می‌کند. پس محصولی که `onlinePrice` نال یا صفر دارد اصلاً در `products` نیاید (و طبعاً در `total`/`max_pages` هم شمرده نشود).
- **محصولاتِ ناموجود بمانند با `availability: false`** — هم‌راستا با چارچوبِ ناموجودیِ خودمان (هرگز حذف/۴۰۴).

## تست
- بدنهٔ خالی و بدنهٔ نامعتبر → ۴۰۰.
- بدونِ هدرِ توکن، توکنِ دست‌کاری‌شده، توکنِ منقضی، و `aud` غلط → هر چهار ۴۰۱.
- `{"page":1,"sort":"date_added_desc"}` → دقیقاً ۱۰۰ محصول (اگر کاتالوگ اجازه بدهد)، `current_page:1`، `max_pages` درست، و صفحهٔ آخر کمتر از ۱۰۰.
- `page_uniques` با یک id واقعی → همان یک محصول؛ با id ناموجود → آرایهٔ خالی (طبقِ مستندات، برایِ محصولِ حذف‌شده آرایهٔ خالی برمی‌گردد).
- `page_urls` با URLِ هیبریدِ واقعیِ یک محصول → همان محصول.
- یک محصولِ دارایِ `+` در نام (مثلِ `CCR2116-12G-4S+`) را چک کن که `page_url` درست percent-encode شده باشد.
- ⚠️ برایِ ساختنِ توکنِ تستی نمی‌توانی با کلیدِ خصوصیِ ترب امضا کنی؛ برایِ تستِ لوکال یک جفت‌کلیدِ ed25519ِ خودت بساز و کلیدِ عمومیِ کانفیگ را موقتاً با آن عوض کن — **یادت باشد قبل از دیپلوی به کلیدِ واقعیِ ترب برگردانی.**

## بعدِ اتمام
به مدیر گزارش بده. مرحلهٔ بعد (بعدِ DNS/TLS): ثبت‌نامِ فروشگاه در ترب + تماس با پشتیبانی برایِ هماهنگی و تست. `product_webhook` (اطلاع‌رسانیِ آنیِ تغییرات) اختیاری است و فعلاً در اسکوپ نیست.
