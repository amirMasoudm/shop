# پرامپتِ چت الف — رفعِ باگِ سبدِ خرید برایِ ناموجودی (فقط باگ، بدونِ UIِ جدید)

## زمینه
فیلدِ `Product.stock` و JSON-LDِ `availability` (`InStock`/`OutOfStock`) از قبل درست پیاده‌سازی شده‌اند. **تصمیمِ کاربر (۲۰۲۶-۰۸-۱۰): فعلاً برچسبِ «ناموجود» و تغییرِ ترتیبِ لیست پیاده نشود** — بی‌خیالش شدیم، فقط باگِ زیر رفع شود.

## ⚠️ قدمِ صفر — قبل از هر کدی، توزیعِ داده را چک کن
کارِ بازنویسیِ محتوایِ فازِ ۴ هیچ‌وقت فیلدِ `stock` را دست نزد. ممکن است رویِ اکثرِ ۲۶۵ محصول این فیلد null/۰ باشد (نه اینکه واقعاً ناموجود باشند). قبل از هر تغییری، رویِ سرور اجرا کن:
```bash
docker exec shop_mongo mongosh shopdb -u shopadmin -p --authenticationDatabase admin --quiet --eval '
print("total=" + db.products.countDocuments({}));
print("stockPositive=" + db.products.countDocuments({stock:{$gt:0}}));
print("stockZeroOrMissing=" + db.products.countDocuments({$or:[{stock:0},{stock:null},{stock:{$exists:false}}]}));
'
```
**اگر اکثریتِ محصولات `stockZeroOrMissing` بودند، به مدیر گزارش بده و منتظرِ تصمیم بمان — قبلِ رفعِ باگ، کدِ زیر را پیاده نکن**، چون بلاک‌کردنِ افزودن‌به‌سبد بر اساسِ دیتایِ نامعتبر یعنی قفل‌شدنِ خریدِ محصولاتی که واقعاً موجودند.

## ۱. باگِ افزودن‌به‌سبدِ کالایِ ناموجود (فقط اگر قدمِ صفر تأیید کرد دیتا معتبر است)
در `CL.html` خطِ ۱۶۱۸، دکمهٔ «افزودن به سبد» بدونِ هیچ چکِ `stock` رندر و فعال می‌شود.
- اگر `p.stock <= 0`: دکمه غیرفعال شود (بدونِ برچسبِ تزئینیِ اضافه — فقط رفعِ عملکرد).
- سمتِ سرور هم چک شود (`InsufficientStockException` که از قبل هست — مطمئن شو مسیرِ افزودن‌به‌سبد/شروعِ سفارش هم همین را رعایت می‌کند، نه فقط UI).

## ۲. تست
- پنلِ ادمین: `stock` را رویِ یک محصولِ تستی صفر کن، ذخیره شود.
- فروشگاه: همان محصول دیگر قابلِ‌افزودن‌به‌سبد نباشد؛ محصولاتِ باموجودیِ مثبت دست‌نخورده کار کنند.
- گزارشِ نهایی: نتیجهٔ قدمِ صفر (عددها) + تأییدِ رفعِ باگ.

## یادداشت برایِ بعداً (بک‌لاگ، نه الان)
برچسبِ بصریِ «ناموجود» + ترتیبِ لیست، منوط به این است که اول دیتایِ `stock` برایِ کاتالوگ به‌طورِ معتبر پر شود (تصمیمِ جداگانه، بعداً).
