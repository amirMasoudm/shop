# تسکِ چت الف — ربات‌ها نباید در آمارِ مشتری شمرده شوند

کارِ کوچکی است، ولی از هفتهٔ پیش شروع کرده به خراب‌کردنِ دادهٔ ماژولی که سه فاز
رویش کار کردیم.

> **قواعدِ همیشگی:** با pathspec صریح کامیت کن، CHANGELOG را ننویس (کارِ مدیر است)،
> و هیچ رشتهٔ مخصوصِ داده‌نما را در کدِ core هاردکد نکن.

---

## چرا — و چرا **الان**

در کلِ ماژولِ ردگیری هیچ فیلترِ رباتی نیست. سه دروازهٔ ثبت در `UserEventRecorder`
فقط `isStaffTraffic()` را چک می‌کنند.

و این با رفتارِ `VisitorIdentityFilter` ترکیب می‌شود:

```java
String anonId = cookie(request, ANON_COOKIE);
if (anonId == null || !isUuid(anonId)) {
    anonId = UUID.randomUUID().toString();   // ← هر درخواستِ بی‌کوکی، یک هویتِ تازه
```

خزنده کوکی را برنمی‌گرداند. پس **هر درخواستِ گوگل‌بات یک «بازدیدکنندهٔ یکتای تازه»
می‌سازد**، با سشنِ تک‌صفحه‌ای، نرخِ پرشِ صددرصد، و کانالِ `DIRECT`.

🔴 **تا ۲۶ شهریور این بی‌اهمیت بود** چون سرور فقط با آی‌پی در دسترس بود و خزندهٔ
جدی سراغش نمی‌آمد. از لحظهٔ سوییچِ دامنه، یک خزشِ کاملِ نقشهٔ سایت یعنی **۵۲۴
بازدیدکنندهٔ یکتای جعلی** در یک نشست.

این دقیقاً هم‌خانوادهٔ باگی است که در فازِ ۱ با ترافیکِ کارمندان گرفتیم: همان ماژول،
همان سه دروازه. آن یکی در تست دیده شد؛ این یکی چون پیش از سوییچ خاموش بود از چشم
افتاد.

---

## کجا — و چرا **نه** کنارِ `isStaffTraffic()`

وسوسه‌اش این است که یک `isBotTraffic()` کنارِ `isStaffTraffic()` بنویسی و در همان سه
نقطه صدایش بزنی. **این کار را نکن.**

`isStaffTraffic()` از `SecurityContextHolder` می‌خواند و به درخواست نیاز ندارد. ولی
تشخیصِ ربات به **User-Agent** نیاز دارد، یعنی به `HttpServletRequest` — و یکی از
همان مسیرها (`record` با امضای `AnalyticsContext`) ممکن است درخواست در دستش نباشد.
اگر آنجا سراغِ `RequestContextHolder` بروی، یک وابستگیِ پنهان به نخِ درخواست
می‌سازی که در جابِ شبانه و نخِ پس‌زمینه می‌شکند.

**جای درست: `VisitorIdentityFilter.establish()`** — آنجا درخواست حتماً هست و
User-Agent همین حالا برای `deviceOf()` خوانده می‌شود.

```java
String ua = request.getHeader("User-Agent");
if (isCrawler(ua)) return;     // نه کوکی، نه زمینه، نه رویداد
```

با همین یک `return`، **هیچ تغییری در `UserEventRecorder` لازم نیست** — چون هر سه
دروازه از قبل با `ctx == null` برمی‌گردند:

```
line ~101 : if (ctx == null || type == null) return;
line ~143 : if (ctx == null || ctx.anonId() == null) return;
line ~191 : if (ctx == null || ctx.anonId() == null) return;
```

کمترین سطحِ تماس، کمترین ریسک. **این را تأیید کن و در گزارش بنویس** که واقعاً هر سه
مسیر با `ctx` نال ساکت می‌مانند — اگر جایی پیدا کردی که بدونِ زمینه هم می‌نویسد،
همان‌جا بایست و گزارش بده.

سودِ جانبی: دیگر روی هر صفحهٔ خزیده‌شده سه هدرِ `Set-Cookie` بی‌مصرف نمی‌نشیند.

---

## تشخیص — فهرستِ نشانه‌ها، نه حدس

مطابقتِ زیررشته‌ایِ **کوچک‌شده** روی User-Agent. حداقل این نشانه‌ها:

```
bot  crawler  spider  crawl  slurp  fetcher  archiver  monitor
googlebot  bingbot  yandex  duckduckbot  baiduspider  applebot
facebookexternalhit  twitterbot  telegrambot  whatsapp  skypeuripreview
ahrefs  semrush  mj12bot  dotbot  petalbot  dataforseo  screaming frog
gptbot  claudebot  ccbot  perplexitybot  bytespider
headlesschrome  phantomjs  puppeteer  playwright  python-requests  curl/  wget
```

⚠️ **User-Agentِ خالی را ربات حساب نکن.** مرورگرهای واقعی پشتِ بعضی پروکسی‌ها
هدر را حذف می‌کنند و اگر خالی را ربات بگیریم، مشتریِ واقعی از آمار حذف می‌شود —
یعنی دقیقاً همان اشتباهی که با `ROLE_ANONYMOUS` نزدیک بود مرتکب شویم. خالی =
انسانِ ناشناس، همان رفتارِ فعلی.

⚠️ فهرست را در `application.properties` **قابلِ تنظیم** کن با همین مقدار به‌عنوان
پیش‌فرض (مثلاً `analytics.crawler-tokens`)، تا افزودنِ خزندهٔ تازه استقرار نخواهد.
پیش‌فرض باید کار کند اگر پراپرتی نبود.

---

## دادهٔ آلودهٔ موجود — پاکش نکن

از ۲۶ شهریور تا امروز، رویدادهای رباتی داخلِ `user_events` هست.

🔴 **تلاش برای پاک‌کردنشان نکن.** چون User-Agent ذخیره نمی‌شود، هیچ راهِ قطعی برای
تشخیصشان نداریم و هر حذفِ حدسی، دادهٔ واقعیِ مشتری را هم می‌برد. حذفِ اشتباه
برگشت‌ناپذیر است؛ دادهٔ آلوده با یک پانویس قابلِ تحمل است.

فقط **تاریخِ دقیقِ اعمالِ فیلتر** را در گزارشت بنویس تا مدیر در CHANGELOG ثبت کند و
مقایسه‌های آینده بدانند از کجا داده تمیز است.

---

## آنچه نمی‌خواهیم

شمارندهٔ خزنده در پنل **ساخته نشود**. لاگِ nginx و سرچ کنسول همین را بهتر می‌دهند،
و طبقِ همان قاعده‌ای که دربارهٔ Semrush داشتیم، چیزی که ابزارِ رایگان می‌دهد را
خودمان نمی‌سازیم. ربات فقط **حذف** می‌شود، جای دیگری ثبت نمی‌شود.

---

## معیارِ پذیرش

تست با دو `curl` پشتِ هم روی همان مسیر، و شمارشِ `user_events` قبل و بعدِ هرکدام:

- [ ] با `-A 'Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)'`
      → **هیچ رویدادی ثبت نشود** و **هیچ `Set-Cookie`ی** برنگردد.
- [ ] با User-Agentِ یک مرورگرِ واقعی → رویداد **مثلِ قبل ثبت شود**. این مهم‌ترین
      تستِ منفی است: اگر این بشکند، کلِ آمارِ مشتری خاموش می‌شود.
- [ ] **بدونِ هدرِ User-Agent** → رویداد ثبت شود (خالی ≠ ربات).
- [ ] با `-A 'AhrefsBot/7.0'` → ثبت نشود.
- [ ] خودِ صفحه در هر سه حالت `200` بدهد و محتوایش فرقی نکند — فیلتر نباید روی
      خروجیِ سایت اثر بگذارد. 🔴 **مخصوصاً برای گوگل‌بات**: اگر به خزنده محتوای
      متفاوتی بدهیم، مصداقِ cloaking است و جریمه دارد. فقط ردگیری خاموش می‌شود،
      نه چیزِ دیگری.
- [ ] پراپرتیِ نبودن در `application.properties` → فهرستِ پیش‌فرض کار کند.
