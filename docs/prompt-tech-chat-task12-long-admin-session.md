# تسک ۱۲ (چت الف) — سشنِ ادمینِ ماندگار در MongoDB (تا چت ب مدام لاگین نکند)

## چرا
چت ب حجمِ زیادی کارِ پنل (ورودِ محصول) دارد و پیش‌فرضِ سشن (۳۰ دقیقه، در RAM) باعثِ لاگینِ مکرر می‌شود. کاربر می‌خواهد **حتی با خاموش‌کردنِ لپ‌تاپ/داکر** لاگین بماند.

> **نکتهٔ کلیدی:** سشنِ پیش‌فرضِ اسپرینگ **درونِ حافظه (RAM)** است. چون سرور همان داکرِ روی لپ‌تاپِ کاربر است، خاموش‌شدنِ لپ‌تاپ → توقفِ کانتینر → پاک‌شدنِ سشن‌های RAM → لاگینِ دوباره. پس صرفِ بلندکردنِ timeout کافی نیست؛ سشن باید **در MongoDB ذخیره شود** تا ری‌استارتِ برنامه/داکر را رد کند. (مونگو همین حالا در استک هست.)

## اصلِ حاکم (امنیت نشکند)
❌ **احرازِ هویت را برندار.** `SecurityConfig.java` **دست‌نخورده** بماند؛ همه‌ی `hasRole("ADMIN")`ها سرِ جا. این برنچ `security-hardening` است.
✅ فقط **محلِ ذخیره‌ی سشن** (RAM → Mongo) و **عمرِ سشن/کوکی** عوض می‌شود. کاربر همچنان کاملاً احرازشده است؛ صرفاً سشنش پایدار و طولانی‌تر می‌شود.

## کار

### ۱) وابستگی (pom.xml)
دپندنسیِ Spring Session Data MongoDB را اضافه کن (کنارِ بقیه‌ی starterها):
```xml
<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-data-mongodb</artifactId>
</dependency>
```
(نسخه از BOMِ اسپرینگ‌بوت می‌آید — نیازی به `<version>` نیست.)

### ۲) کانفیگ (`src/main/resources/application.properties`)
```properties
# سشنِ ادمین در MongoDB ذخیره شود تا ری‌استارتِ داکر/لپ‌تاپ را رد کند
spring.session.store-type=mongodb
spring.session.mongodb.collection-name=sessions
# عمرِ سشن و کوکیِ ماندگار — ۳۰ روز
server.servlet.session.timeout=30d
server.servlet.session.cookie.max-age=30d
```
- `store-type=mongodb` → سشن در کالکشنِ `sessions` مونگو ذخیره می‌شود (پایدار در ری‌استارت).
- `session.timeout=30d` → سشن ۳۰ روز اعتبار دارد (Spring Session همین مقدار را برای انقضا می‌خواند؛ TTL indexِ مونگو خودکار ساخته می‌شود).
- `cookie.max-age=30d` → کوکیِ سشن ماندگار می‌شود (بعدِ بستنِ مرورگر/خاموشیِ لپ‌تاپ پاک نمی‌شود).

> اگر پروژه چند پروفایل دارد و می‌خواهی محتاط باشی، می‌توانی این بلاک را در `application-dev.properties` بگذاری؛ ولی چون فقط سشنِ کاربرِ **احرازشده** را پایدار می‌کند (نه بازکردنِ چیزی)، روی پراد هم بی‌خطر است — بلکه بهتر است (لاگینِ ادمین بعدِ دیپلوی/ری‌استارتِ داکر هم می‌ماند).

## تست
1. `mvn clean package -DskipTests` سپس `docker compose up -d --build`.
2. با ادمین لاگین کن → `Admin.html` باید ۲۰۰ بدهد.
3. **کالکشنِ `sessions` در مونگو ساخته شده و یک داکیومنتِ سشن دارد** (چک کن؛ اثباتِ ذخیره‌ی پایدار).
4. کوکیِ سشن در DevTools باید `Expires/Max-Age` داشته باشد (نه «Session»).
5. **تستِ ماندگاری (اصلِ کار):** `docker compose restart` (یا `down` سپس `up`) بزن → **بدونِ لاگینِ دوباره** به `Admin.html` برو → باید همچنان ۲۰۰ بدهد (سشن از مونگو بازیابی شد).
6. **تستِ منفیِ امنیت (مهم):** یک `PUT /api/v1/products/{id}` **بدونِ کوکیِ لاگین** (مثلاً curl) → باید همچنان **۴۰۱/۴۰۳** بدهد. اگر ۲۰۰ داد یعنی سهواً auth شکسته — متوقف شو و به مدیر بگو.

## کامیت
با pathspec صریح، فقط دو فایل:
`git commit -- pom.xml src/main/resources/application.properties`
پیامِ کامیت: «تسک ۱۲: سشنِ ادمینِ ماندگار در MongoDB (۳۰ روز) — کاهشِ لاگینِ مکررِ چت ب؛ امنیت/نقش‌ها دست‌نخورده».
