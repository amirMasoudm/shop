# تسکِ چت الف — اتصالِ مکانیزمِ ریدایرکت به دکمهٔ حذفِ محصول در پنل

## مسئله
کالکشنِ `product_redirects` و APIاش (`/api/v1/product-redirects`) از قبل ساخته و تست شده‌اند (کامیتِ `8552f60`)، ولی **به هیچ‌جای پنل وصل نیستند.** الان دکمهٔ حذفِ محصول در `Admin.html` بدونِ هیچ پرسشی مستقیم `DELETE /api/v1/products/{id}` می‌زند. یعنی اگر کسی محصولی را حذف کند و یادش نرود ریدایرکت را دستی بسازد، آدرسِ آن محصول ۴۰۴ می‌شود.

**هدف:** فرآیندِ حذفِ محصول در پنل خودش این پرسش را بکند و ترتیبِ امن را اجباری کند، تا دیگر به یادِ کسی وابسته نباشد.

## چیزی که باید بسازی — فقط در `Admin.html` (فرانت)

وقتی ادمین دکمهٔ حذفِ یک محصول را می‌زند:

۱. **قبل از حذفِ واقعی**، یک دیالوگ (با همان کتابخانهٔ SweetAlert2 که پروژه از قبل استفاده می‌کند، نه `confirm()` خام) بپرس:
   > «آیا آدرسِ این محصول به محصولِ دیگری ریدایرکت شود؟ (اگر این محصول تکراری/ادغام‌شونده است، بله؛ اگر هرگز منتشر/ایندکس نشده، رد کن.)»
   با سه گزینه: **ریدایرکت به محصولِ دیگر** / **رد کن، مستقیم حذف کن** / **انصراف**.

۲. اگر «ریدایرکت» انتخاب شد: یک انتخاب‌گرِ محصول نشان بده (از همان الگویِ جست‌وجو/انتخابِ محصولی که برایِ «محصولاتِ مرتبط» در پنل از قبل هست، استفاده کن — دوباره نساز).

۳. با انتخابِ محصولِ مقصد، `POST /api/v1/product-redirects` بزن با `fromSlug` = اسلاگِ محصولِ در‌حالِ‌حذف و `toResolver` = اسلاگ/شناسهٔ محصولِ مقصد. ⚠️ **اول در کدِ `ProductRedirectService`/`ProductUrlUtil` ببین کدام فیلد (`slug` یا `persianSlug`) را `resolveProduct` واقعاً برایِ تطبیق می‌خواند** — حدس نزن.

۴. جوابِ API فیلدِ `targetResolves` دارد. اگر `false` بود، هشدارِ صریح نشان بده («مقصد الان به محصولِ زنده‌ای نمی‌رسد») و بگذار ادمین تصمیم بگیرد ادامه بدهد یا لغو کند.

۵. **فقط بعدِ موفقیتِ ثبتِ ریدایرکت** (یا انتخابِ «رد کن»)، درخواستِ حذفِ واقعی زده شود.

۶. اگر «رد کن، مستقیم حذف کن» انتخاب شد، یک تاییدِ نهاییِ کوتاه بزن («این کار آدرسِ محصول را ۴۰۴ می‌کند — مطمئنی هرگز منتشر/ایندکس نشده؟») چون قانونِ سئویِ پروژه صریح می‌گوید هرگز ۴۰۴ ندهیم مگر عمدی و آگاهانه باشد.

## قیدها
- ⛔ **فقط مسیرِ حذفِ محصول را عوض کن.** حذفِ دسته/مقاله/سکشن دست‌نخورده بماند — آن‌ها اسلاگِ محصول ندارند و این مکانیزم برایشان معنا ندارد.
- ⛔ بک‌اند را تغییر نده مگر چیزی واقعاً کم باشد (مثلاً اگر آبجکتِ محصول در پنل اسلاگِ فعلی را نداشته باشد و لازم شود اضافه شود) — اگر چنین چیزی لازم شد، در گزارش بگو چرا، خودسرانه چیزِ اضافه نساز.
- ⛔ فقط لوکال. کامیتِ pathspec صریح.

## تست
- ساختِ یک محصولِ آزمایشی + یک محصولِ مقصدِ آزمایشی → حذف با گزینهٔ «ریدایرکت» → آدرسِ قدیمی باید ۳۰۱ به مقصد بزند.
- حذف با گزینهٔ «رد کن» → محصول حذف می‌شود، هیچ ریدایرکتی ساخته نمی‌شود.
- «انصراف» → هیچ‌چیز حذف نمی‌شود.
- رگرسیون: حذفِ یک دسته/مقاله/سکشن هنوز مثلِ قبل کار می‌کند.
- بعد از تست، دادهٔ آزمایشی را کامل پاک کن (هم محصول‌ها هم رکوردِ ریدایرکت) — همان انضباطِ چت الف در تسکِ قبلی.
