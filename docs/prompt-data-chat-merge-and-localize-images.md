### قبل از هر حذفی
- مطمئن شو ریدایرکت واقعاً کار می‌کند: آدرسِ قدیمیِ B را باز کن، باید ۳۰۱ به A بدهد، **قبل از** حذفِ B.
- بعدِ حذف، دوباره همان آدرسِ قدیمی را چک کن — باید هنوز ۳۰۱ بدهد (نه ۴۰۴)، چون خودِ رکورد رفته ولی نگاشتِ ریدایرکت باید بماند.

## بخشِ ۲ — لوکال‌کردنِ ۹ عکسِ لینکی (رفعِ ریسکِ پایداری)

۹ محصولی که عکسشان لینکِ خارجی است (۵ یوبیکیوتی/میموسا + ۴ فنویل) — فایل‌هایِ واقعی از قبل دانلود شده‌اند، نیازی به دانلودِ دوباره نیست:
```
data-import/relinked-product-images/
```
۲۵ فایل، نام‌گذاریِ `{کدِ محصول}_{شماره}.jpg` (مثلاً `v62g_1.jpg`, `v62g_2.jpg`, `v62g_3.jpg`).

نگاشتِ نام‌به‌محصول:
| پیشوندِ فایل | محصول |
|---|---|
| `c6x` | رادیو میموسا C6x |
| `u6meshpro` | یوبیکیوتی U6 Mesh Pro *(اگر بخشِ ۱-الفِ گزارش هنوز حل‌نشده مانده — ردیفِ ۱۳۷ — این محصول شاید اصلاً حذف/ادغام شود؛ قبل از این کار وضعیتش را چک کن)* |
| `u6plus` | یوبیکیوتی UniFi U6+ |
| `u7lite` | یوبیکیوتی UniFi U7 Lite |
| `u7lr` | یوبیکیوتی UniFi U7 LR |
| `v61w` | فنویل V61W |
| `v62g` | فنویل V62G |
| `x1sp` | فنویل X1SP |
| `x303p` | فنویل X303P |

**کار برایِ هر محصول:**
۱. هر فایل را با همان مکانیزمِ آپلودِ پنل (همان endpointِ `POST /v1/files/upload` که Admin.html استفاده می‌کند) آپلود کن تا آدرسِ لوکالِ `/uploads/{uuid}.jpg` بگیرد.
۲. آرایهٔ `images` محصول را از لینکِ خارجی به آدرس‌هایِ جدیدِ لوکال عوض کن — **با همان ترتیب** (شمارهٔ فایل = جایگاه در آرایه)، چون `imageAlts` موازیِ همین ترتیب است و نباید جابه‌جا شود.
۳. لینکِ خارجیِ قدیمی از `images` کاملاً حذف شود (جایگزین، نه اضافه).

### ⚠️ نکتهٔ پنجِ آداپتورِ یوبیکیوتی (ردیف‌هایِ ۲۰۱–۲۰۵)
این‌ها هم عکسِ لینکی از `images.svc.ui.com` دارند ولی در فولدرِ بالا **نیستند** (دانلود نشده بودند). اگر وقت داشتی همین کار را برایِشان هم بکن (۵ محصولِ دیگر، ۴ عکسِ رسمی هرکدام) — دانلودِ سمتِ سرور (نه مرورگر) مشکلِ CORS ندارد، فقط `curl`/فچِ سروری از همان آدرس‌هایِ ثبت‌شده در `images` کافیست.

### تست
- بعدِ هر محصول، صفحهٔ زندهٔ آن را باز کن — عکس‌ها باید از `/uploads/...` بیایند، نه از دامنهٔ خارجی.
- مطمئن شو `imageAlts` هنوز با عکسِ درست جفت است (متن‌هایِ توصیفی جابه‌جا نشوند).
