# سوارشدنِ چتِ تازهٔ محتوا — این را اول بخوان

تو یکی از **سه** چتی هستی که هم‌زمان روی بازنویسیِ مقالاتِ بلاگِ داده‌نما کار
می‌کنند. این سند تو را در ده دقیقه سوار می‌کند. همهٔ گفتگو فارسی است.

## ۱) سه سندی که باید بخوانی، به همین ترتیب

| سند | چرا |
|---|---|
| `docs/article-rewrite-handover.md` | چرا این کار شروع شد، چه تمام شده، و **بخشِ ۷: دوازده درسی که هر کدام از یک اشتباهِ واقعی درآمده**. سرسری نگیر. |
| `docs/prompt-data-chat-article-rewrite-loop.md` | قواعدِ حاکم بر هر مقاله. از جمله **«کجا کار کن، و چطور وارد شو»**. |
| پرامپتِ بستهٔ خودت | `docs/prompt-data-chat-article-rewrite-batch-<بسته>.md` |

## ۲) نقشِ تو

تو **مجری** هستی: از پنلِ ادمینِ **سرورِ زنده** کار می‌کنی، و در پایانِ هر بسته
گزارشِ تفصیلی می‌دهی. `CHANGELOG.md` را **ننویس** — فقط مدیر می‌نویسد.
`activity_logs` هرگز دست نمی‌خورد. هیچ مقاله‌ای حذف نمی‌شود.

چت‌ها مستقیم با هم حرف نمی‌زنند؛ **مالک همهٔ پیام‌ها را دست‌به‌دست می‌کند.**

---

## ۳) 🔴 سه چت هم‌زمان کار می‌کنند — چیزهایی که قبلاً درست بود، حالا نیست

تا امروز هر بار فقط یک چت روی دادهٔ زنده کار می‌کرد. دیگر این‌طور نیست، و سه
چیز از این تغییر بیرون می‌آید:

**الف) از بستهٔ خودت بیرون نرو.** تقسیم سفت است:

```
chat B  ->  baste D   (94 maghale — aks-e shekaste)
chat ?  ->  baste F   (34 maghale — maghale-ye vaghei, faghat bazbini)
chat ?  ->  baste G   (26 maghale — baghi)
```

اگر حینِ کار به مقاله‌ای برخوردی که مالِ بستهٔ دیگری است — حتی اگر ایرادش
آشکار باشد — **دست نزن**، فقط در گزارش بنویس. دو چت که یک مقاله را ذخیره کنند،
کارِ هم را بی‌صدا پاک می‌کنند.

**ب) 🔴 شمارشِ کلِ ریدایرکت‌ها دیگر معیارِ معتبری نیست.** روشِ قبلی این بود که
پیش و پسِ کار تعدادِ کلِ ریدایرکت‌های سایت شمرده شود و اگر عوض نشده بود یعنی
اسلاگی سهواً عوض نشده. **الان دو چتِ دیگر هم‌زمان دارند ریدایرکت می‌سازند**، پس
آن عدد زیرِ پایت تکان می‌خورد و هر نتیجه‌ای از آن بگیری غلط است.

به‌جایش **فقط آدرس‌به‌آدرس بسنج**:

```
curl -sL --noproxy '*' -w '%{http_code}|%{num_redirects}' <URL>
```

معیار همیشه **یک پرش** است، نه فقط ۲۰۰.

**ج) گیت مشترک است.** همیشه با pathspecِ صریح کامیت کن:

```
git commit -m "..." -- docs/reports/<file>
```

هرگز `git add .` نزن. فایلِ تازه اول `git add -- <file>`.

## ۴) چهار چیزی که اگر ندانی خرابی می‌سازی

**۱ — اطلاعاتِ تماس در متنِ مقاله‌ها پاک نمی‌شود.** لینکِ تلگرام، نشانی، شمارهٔ
تلفن و نامِ افراد می‌مانند. قاعدهٔ ضدِ دور‌زدنِ پروژه فقط برای ساختارِ سایت و
متنِ محصولات است.

🔴 **و این تله دو بار خورده شده:** ستونِ `kar-e lazem` در
`docs/reports/article-audit-2026-09-21.csv` برای ده‌ها مقاله نوشته
`hazf-e telegram`. **آن ستون کهنه است و اجرا نمی‌شود** — پیش از تصحیحِ صریحِ
مالک ساخته شده. یک بار در بستهٔ B-۱ همین حذف شد و با یک تسکِ جدا برگردانده شد.

**۲ — دادهٔ محتوا روی سرورِ زنده است، نه لوکال.** نسخهٔ لوکال عقب مانده. هر
تغییری فوراً روی سایتِ عمومی است.

**۳ — مقالهٔ منتشرشده با تغییرِ اسلاگ باید ریدایرکت بگیرد:** در دیالوگِ پنل
جوابِ **«بله»**. و ⚠️ اسلاگ را **دو بار** عوض نکن؛ هر بار یک ریدایرکت می‌سازد.

**۴ — مسیرِ فارسیِ درصد-کدگذاری‌نشده معنی ندارد.** تامکت مسیرِ خامِ غیر‌ASCII را
با **۴۰۰** رد می‌کند. همیشه شکلِ درصد-کدگذاری‌شده را تست کن، وگرنه نتیجهٔ تست
دروغ است.

---

## ۵) ⚠️ یک باگِ زندهٔ سایت که باید بشناسی

آدرسِ **ناموجودِ** بلاگ الان ۴۰۴ نمی‌دهد؛ **۳۰۱ به خودش** می‌دهد و در حلقه
می‌افتد. سنجیده شده:

```
/blog/yek-adrese-bi-mani-12345   ->  301 ... 301 ... (halghe)
```

**یعنی چه برای تو:** اگر آدرسی را تست کردی و دیدی چند پرش می‌خورد و به جایی
نمی‌رسد، لزوماً کارِ تو خراب نشده — شاید اصلاً آن اسلاگ وجود ندارد (تایپی در
تست). **اول اسلاگ را از پنل کنترل کن، بعد نگران شو.** رفعِ خودِ باگ کارِ چت الف
است و به مدیر گزارش شده.

---

## ۶) گزارش

برای **هر مقاله** یک سطر:

```
aslug | vajeh ghabl -> ba'd | aks-e hazf-shode | video | onvan? | aslug? | redirect? | meta?
```

و در پایان: چند مقاله نامفهوم بود · کدام‌ها تاریخ/شهرشان معلوم نشد · کدام‌ها
ثبتِ ریدایرکتشان خطا داد · هر خوشه‌ای که غلط به‌نظرت می‌رسد (خوشه را **سرخود
عوض نکن**) · هر مقاله‌ای از بستهٔ دیگران که ایراد داشت.

🔴 گزارشِ «همه انجام شد» بدونِ این جزئیات پذیرفته نمی‌شود.
