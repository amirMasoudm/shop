# تسکِ چت الف — فازِ ۱ زیرساختِ خطاها: صفحهٔ خطای فارسی با کدِ درست

طرحِ کامل در `docs/plan-error-infrastructure.md`. این فازِ ۱ است و با فازِ ۲ (کارِ
چت ج روی nginx) موازی است — به هم کاری ندارند.

> **قواعدِ همیشگی:** با pathspec صریح کامیت کن، CHANGELOG را ننویس (کارِ مدیر است)،
> هیچ رشتهٔ مخصوصِ داده‌نما را در کدِ core هاردکد نکن، و بیلد و استقرار را خودت نزن —
> دستور را بده.

---

## چرا — این همین حالا روی سایتِ زنده است

اندازه‌گیریِ واقعی، نه حدس. یک مسیرِ مرده روی `dadehnama.com` با هدرِ `Accept`ِ یک
مرورگرِ واقعی این را برمی‌گرداند:

```
<html><body><h1>Whitelabel Error Page</h1>
<p>This application has no explicit mapping for /error, so you are seeing this
   as a fallback.</p>
<div>There was an unexpected error (type=Not Found, status=404).</div>
</body></html>
```

روی یک فروشگاهِ فارسی. علتش ساده است: هشت قالبِ Thymeleaf داریم و **هیچ‌کدام برای
خطا نیست**.

و همان مسیر با `Accept: */*` پاسخِ `application/json` خام می‌دهد. یعنی
**تست‌های `curl`ِ خودت هم صفحه‌ای را که می‌سازی نمی‌بینند** — این را پایین‌تر حل
می‌کنیم.

خبرِ خوب که وقتت را آزاد می‌کند: **استک‌تریس نشت نمی‌کند.** تستِ زنده روی یک مسیرِ
نامعتبرِ API فقط چهار فیلدِ ساده برگرداند. نگرانیِ امنیتیِ کلاسیکِ صفحهٔ خطا اینجا
وجود ندارد، پس سراغش نرو.

---

## 🔴 مهم‌ترین بندِ این تسک — فالبکِ ۴۰۴ت را نشکن

کارِ خودت در `fd34c5c` (`LegacyPathErrorController`) دقیقاً همان‌جایی نشسته که این
فاز هم به آن دست می‌زند. خوشبختانه معماری‌اش درست است و **لازم نیست دست بخورد**:

```
LegacyPathErrorController.errorHtml()
    |
    +-- fallback.resolve() != null  ->  301  (safheh-ye khata render nemishavad)
    |
    +-- fallback.resolve() == null  ->  super.errorHtml()  <- inja ghaleb miayad
```

چون `BasicErrorController.errorHtml` خودش `resolveErrorView` را صدا می‌زند و
`DefaultErrorViewResolver` قالبِ `error/404` را پیدا می‌کند، **افزودنِ قالب بدونِ
هیچ تغییری در کنترلر کار می‌کند**.

پس: **قالب اضافه کن، کنترلر را بازنویسی نکن.** اگر وسوسه شدی منطقِ خطا را جمع و
جور کنی، نکن — آن ارث‌بری تنها چیزی است که تضمین می‌کند وقتی فالبک جوابی ندارد
رفتارِ پیش‌فرض دست‌نخورده بماند.

---

## کار

### یک — دو قالب، نه یکی

از قرارِ نامیِ خودِ اسپرینگ استفاده کن تا `DefaultErrorViewResolver` خودش پیدایشان
کند:

```
src/main/resources/templates/error/404.html
src/main/resources/templates/error/5xx.html
```

هم‌شکلِ بقیهٔ سایت: همان هدر، همان فوتر، همان فونت. از قالب‌های موجود
(`about.html`, `blog.html`) الگو بگیر تا ظاهر ناگهان عوض نشود.

**متنِ ۴۰۴** — لحنِ «این صفحه نیست، ولی چیزی که می‌خواهی احتمالاً هست»، با راهِ
خروج. **متنِ ۵xx** — لحنِ «مشکل از سمتِ ماست، چند دقیقه بعد دوباره تلاش کن». این دو
پیامِ متفاوت‌اند و یک قالبِ مشترک با `if` هر دو را بد می‌کند.

### دو — راهِ خروجِ ۴۰۴

سه لینک: جست‌وجو، فروشگاه، بلاگ. اگر جست‌وجوی سایت ورودیِ ساده‌ای دارد، همان‌جا
یک کادرِ جست‌وجو بهتر از لینک است.

🔴 **و این‌جا تلهٔ اصلیِ طراحی است: شمارهٔ تماس و فرمِ تماس نگذار.** غریزهٔ اولِ هر
کسی روی صفحهٔ ۴۰۴ گذاشتنِ «تماس با ما» است. قاعدهٔ ضدِ دور‌زدنِ ما این را در
ساختارِ سایت ممنوع می‌کند و صفحهٔ تماس هم عمداً نداریم. راهِ خروج، لینک به فروشگاه
و بلاگ است، نه شمارهٔ تلفن.

### سه — 🔴 کدِ وضعیت هرگز عوض نشود

صفحهٔ قشنگِ ۴۰۴ که با `200` سرو شود می‌شود **soft-404** — همان چیزی که در تحلیلِ
سئو صریحاً ردش کردیم و دلیلِ رهاکردنِ ۹۰ آرشیوِ ووکامرس بود.

- `404` بماند `404`، `500` بماند `500`.
- روی صفحهٔ ۴۰۴ هدرِ `X-Robots-Tag: noindex`.
- روی ۵xx هدرِ `noindex` **نگذار** — گوگل باید بفهمد خطا موقتی است و صفحه را نگه
  دارد. (همان درسِ ۴۴۴: پیامِ غلط بدتر از پیامِ نبودن است.)

### چهار — رفتار به هدرِ `Accept` گره نخورد

قاعده: مسیرهای `‎/api/**` همیشه JSON، بقیه همیشه HTML — حتی با `Accept: */*`.

دلیلش عملی است: **معیارهای پذیرشِ خودت با `curl` گرفته می‌شوند** و `curl` پیش‌فرض
`*/*` می‌فرستد. اگر این را درست نکنی، تست‌هایت JSON می‌بینند و صفحه‌ای که ساختی
هرگز آزموده نمی‌شود.

---

## ⚠️ دست نزن به

- **`LegacyPathFallback` و منطقِ سه قاعده.** آزموده شده و ۹ تستِ واحد دارد.
- **`‎/l/{code}`** — رفتارِ فعلی‌اش حفظ شود.
- **`robots.txt` و `sitemap.xml`** — دست‌نخورده.
- **`GlobalExceptionHandler`** — گستردنش کارِ فازِ ۳ است، نه این فاز. اینجا فقط
  صفحه ساخته می‌شود.

---

## معیارِ پذیرش

با `curl -sL --noproxy '*' -w '%{http_code}|%{num_redirects}'` روی سایتِ زنده:

- [ ] مسیرِ بی‌معنا با `Accept`ِ مرورگر → صفحهٔ **فارسی** با کدِ `404`
- [ ] همان مسیر با `Accept: */*` → همان صفحهٔ HTML و همان کدِ `404` (نه JSON)
- [ ] `‎/api/v1/چیزی-که-نیست` → **JSON** با کدِ درست، نه صفحهٔ HTML
- [ ] هدرِ `X-Robots-Tag: noindex` روی ۴۰۴ هست، روی ۵xx **نیست**
- [ ] 🔴 رگرسیونِ فالبک — هر چهار مورد همچنان یک‌پرشی به `200`:
      `‎/shop/` · `‎/keyloggers/` · `‎/mtctce-06-97/` · `‎/product/qrt-5/`
- [ ] `‎/l/{code}` رفتارِ فعلی
- [ ] `‎/robots.txt` و `‎/sitemap.xml` دست‌نخورده، و در `robots.txt` همچنان
      `Sitemap: https://dadehnama.com/sitemap.xml`
- [ ] صفحهٔ ۴۰۴ روی موبایل (۳۷۵ پیکسل) بدونِ اسکرولِ افقی
- [ ] در صفحهٔ ۴۰۴ **هیچ شماره و ایمیل و فرمِ تماسی** نیست
- [ ] `activity_logs` دست‌نخورده
