# تسکِ چت الف — محکم‌کاریِ API ترب پیش از اولین تماسِ واقعی

ترب ۸ مهر جواب داد که رباتش قیمت و موجودی را از صفحهٔ بدونِ جاوااسکریپت
نمی‌تواند بخواند، و دو راه پیشنهاد کرد: متاتگ، یا API نسخهٔ ۳. **ما راهِ API را
می‌رویم**، چون `TorobApiController` از قبل ساخته شده و کلیدِ «نمایش در ترب» را هم
رعایت می‌کند.

این کد هرگز با توکنِ واقعیِ ترب اجرا نشده و **هیچ تستی ندارد**. چهار کارِ زیر
کوچک‌اند و قرار نیست ساختار عوض شود.

> **قواعدِ همیشگی:** با pathspec صریح کامیت کن، CHANGELOG را ننویس، رشتهٔ مخصوصِ
> داده‌نما در کدِ core هاردکد نکن. بیلد و تستِ کدِ خودت کارِ خودت است.
>
> **اولویت:** بعد از `docs/prompt-tech-chat-partner-unit-fixes-1405-07-08.md`.

# کارِ ۱ — `old_price` از فیلدِ میراثی خوانده می‌شود

```java
long old = toToman(p.getPrice());
if (old > current) m.put("old_price", old);
```

`price` میراثِ وردپرس است و هیچ ربطی به «قیمتِ پیش از تخفیف» ندارد. روی لوکال
همین حالا کالایی هست با `onlinePrice = 98000` و `price = 7000000`؛ با این کد در
ترب «تخفیفِ ۹۸ درصدی» نمایش داده می‌شد.

**کار:** `old_price` کلاً فرستاده نشود. فروشگاه سازوکارِ تخفیف ندارد، پس منبعِ
درستی برایش وجود ندارد. فیلد اختیاری است.

# کارِ ۲ — `spec` از فیلدِ اشتباه پر می‌شود

```java
m.put("spec", p.getSpecifications() == null ? Map.of() : p.getSpecifications());
```

روی لوکال از ۱۵۵ کالای واجدِ شرایط، هر ۱۵۵ تا `techSpecs` دارند ولی فقط ۱۱۱ تا
`specifications`. یعنی ۴۴ کالا با مشخصاتِ خالی به ترب می‌روند، درحالی‌که جدولِ
مشخصاتشان روی سایت کامل است.

**کار:** `spec` از همان منبعی ساخته شود که جدولِ مشخصاتِ صفحهٔ محصول را می‌سازد.
اگر هر دو فیلد پر بودند، همان اولویتی که صفحهٔ محصول دارد. مقدارها رشته یا عدد
باشند (`dict[str, str | int]`)، و خالی همچنان `{}`.

# کارِ ۳ — متنِ گارانتی در کد هاردکد است

```java
private static final String GUARANTEE = "ضمانت اصالت کالا";
```

هم خلافِ قاعدهٔ «هستهٔ عمومی» است، هم برای همهٔ کالاها یک ادعای یکسان می‌فرستد.

**کار:** به `StoreSettings` برود، با پیش‌فرضِ **خالی**. اگر خالی بود فیلدِ
`guarantee` اصلاً فرستاده نشود (اختیاری است). در تنظیماتِ پنلِ ادمین قابلِ ویرایش.

# کارِ ۴ — تست

دو کلاسِ تست، بدونِ وابستگیِ تازه. جفت‌کلیدِ `Ed25519` را داخلِ خودِ تست بساز و
کلیدِ عمومی‌اش را به سرویس بده.

**`TorobTokenService`:**

- توکنِ درست با `aud` برابرِ هاست → معتبر
- امضای دستکاری‌شده، `exp` گذشته، `nbf` نرسیده، `aud` هاستِ دیگر، توکنِ خالی،
  ساختارِ دو‌تکه‌ای → همه نامعتبر
- هاستِ پورت‌دار (`dadehnama.com:443`) با `aud` بدونِ پورت → معتبر

**`TorobApiController`:**

- بدنهٔ خالی، دو کلید با هم، `page: 0`، `sort` نامعتبر → `400`
- صفحه‌بندی: ۲۵۰ کالا → صفحهٔ ۱ و ۲ صدتایی، صفحهٔ ۳ پنجاه‌تایی، `max_pages = 3`
- کالای `torobEnabled = false`، بی‌قیمت، بی‌عکس و توقفِ‌تولید در خروجی **نباشند**
- کالای ناموجود در خروجی **باشد** با `availability: false`
- `page_urls` با نشانیِ کدگذاری‌شده و کدگذاری‌نشده هر دو همان کالا را بدهد
- خروجی `old_price` نداشته باشد
