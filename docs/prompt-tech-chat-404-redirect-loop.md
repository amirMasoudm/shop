# تسکِ چت الف — آدرسِ ناموجود به‌جای ۴۰۴، ۳۰۱ به خودش می‌دهد (حلقهٔ بی‌پایان)

## نشانه

هر آدرسِ **ناموجودی** که زیرِ یکی از مسیرهای الگودار باشد، به‌جای ۴۰۴ یک ۳۰۱ به
**خودش** می‌دهد و تا بی‌نهایت تکرار می‌شود. روی پراد سنجیده شد:

```
/blog/nabashad-xyz-123            ->  301 ... 301 ... (halghe)
/blog/hub/nabashad-xyz-123        ->  301 ... 301 ... (halghe)
/shop/product/nabashad-xyz-123    ->  301 ... 301 ... (halghe)
/shop/category/nabashad-xyz       ->  301 ... 301 ... (halghe)

/nabashad-xyz-123                 ->  404  ✅ (dorost)
```

بازتولید:

```bash
curl -sL --noproxy '*' -o /dev/null -w '%{http_code}|%{num_redirects}\n' --max-redirs 4 https://dadehnama.com/blog/nabashad-xyz-123
```

⚠️ بدونِ `--max-redirs` خودِ curl هم تا ۵۰ پرش می‌رود.

## چرا مهم است

گوگل این‌ها را «Redirect error» گزارش می‌کند، نه «صفحه حذف شد». یعنی هر آدرسِ
مرده‌ای که از وردپرسِ قدیم یا از محصولِ حذف‌شده در ایندکس مانده، **هیچ‌وقت پاک
نمی‌شود** و به‌جایش یک خطا در سرچ کنسول می‌نشیند. مرورگرِ کاربر هم پیامِ
«redirected you too many times» می‌دهد که از صفحهٔ ۴۰۴ بدتر است.

⚠️ من قبلاً در گزارشی نوشته بودم «محصولات ۴۰۴ِ درست می‌دهند» — آن را از یادداشتِ
تسکِ ۶ برداشته بودم نه از اندازه‌گیری. **غلط بود**؛ جدولِ بالا اندازه‌گیریِ امروز
است.

## ریشه — پیدا شده

`src/main/java/org/example/shop1/model/service/LegacyPathFallback.java`، در
`targetFor(String path)`، **قاعدهٔ ۱**:

```java
// قاعدهٔ ۱ — همین مسیر بدونِ اسلشِ پایانی هندلرِ واقعی دارد
if (hasGetHandler(path)) {
    log.info("فالبکِ ۴۰۴ [اسلشِ پایانی]: {} → {}", path, path);
    return path;          // 🔴 وقتی path عوض نشده باشد، یعنی ریدایرکت به خودش
}
```

این قاعده برای حالتِ **اسلشِ پایانی** نوشته شده: `/shop/` می‌آید، `cleanPath()`
اسلش را برمی‌دارد و `/shop` برگردانده می‌شود — مقصد با مبدأ فرق دارد و همه‌چیز
درست است.

ولی وقتی آدرس **اسلشِ پایانی ندارد**، `cleanPath()` چیزی عوض نمی‌کند و مقصد
دقیقاً همان مسیرِ درخواست می‌شود. و چون `hasGetHandler` با **الگو** تطبیق می‌دهد
(`@GetMapping("/blog/{slugOrId}")`)، هر `/blog/هرچه` تطبیق می‌خورد — حتی وقتی آن
مقاله وجود ندارد. نتیجه: ۳۰۱ به خودش.

به‌همین دلیل `/nabashad-xyz-123` درست کار می‌کند: هیچ هندلری برای `/{x}` نیست،
پس قاعدهٔ ۱ اصلاً شلیک نمی‌کند.

---

## رفعِ پیشنهادی

قاعدهٔ ۱ فقط وقتی معنی دارد که `cleanPath()` **واقعاً مسیر را عوض کرده باشد**.
پس مقایسه با مسیرِ خامِ درخواست لازم است:

- اگر مسیرِ تمیزشده با مسیرِ اصلی (پس از دیکد) **یکی** بود → قاعدهٔ ۱ رد شود و
  برود سراغ قاعده‌های بعدی، و در نهایت ۴۰۴ِ واقعی.
- اگر فرق داشت (اسلشِ پایانی یا کوئری برداشته شده) → مثل قبل ریدایرکت.

⚠️ **گاردِ سراسریِ «مقصد = مبدأ» را برنگردان.** در کامنتِ خودِ فایل نوشته شده که
نسخهٔ اولِ گارد سراسری بود و قاعدهٔ ۱ را می‌کشت. راهِ درست این است که قاعدهٔ ۱
بداند «آیا چیزی برای اصلاح وجود داشت یا نه»، نه اینکه مقصد را با مبدأ مقایسه کند.

⚠️ و حواست باشد `cleanPath` هم **دیکد** می‌کند هم اسلش را برمی‌دارد. مسیرِ فارسیِ
درصد-کدشده پس از دیکد با رشتهٔ خام فرق دارد ولی **همان مسیر است** — اگر ساده
مقایسه کنی، هر آدرسِ فارسی «عوض‌شده» حساب می‌شود و باگ برمی‌گردد. مقایسه باید
روی شکلِ **دیکدشده** انجام شود.

## آزمون‌هایی که بعدش باید سبز باشند

**باید ۴۰۴ بدهند (الان حلقه می‌زنند):**

```
/blog/nabashad-xyz-123
/blog/hub/nabashad-xyz-123
/shop/product/nabashad-xyz-123
/shop/category/nabashad-xyz
```

**نباید بشکنند — همه باید ۲۰۰ با حداکثر یک پرش بدهند:**

```
/shop/            (aslash-e payani — dalil-e vojudi-ye ghaede-ye 1)
/blog/            (hamintor)
/blog/نحوه-صحیح-بالا-رفتن-از-دکل                 (maghale-ye zende, 200|0)
/تصاویر-آموزشی-فیدر-و-آنتن/                      (masir-e WordPress, bayad 1 paresh bemanad)
/اسلاید-های-فارسی-آموزش-ارتباطات-مایکر/          (hamintor)
/blog/اسلاید-های-فارسی-آموزش-ارتباطات-مایکر      (aslag-e ghadimi, bayad 1 paresh bemanad)
```

🔴 **آدرس‌های فارسی را درصد-کدگذاری‌شده بزن** — تامکت مسیرِ خامِ غیر‌ASCII را با
۴۰۰ رد می‌کند و تست بی‌معنی می‌شود. و `--noproxy '*'` اجباری است.

```bash
curl -sL --noproxy '*' -o /dev/null -w '%{http_code}|%{num_redirects}\n' --max-redirs 4 <URL>
```

⚠️ **مقالات همین الان دستِ سه چتِ محتوا هستند و اسلاگ‌ها در حالِ تغییرند.** برای
آزمونِ «نباید بشکند» یک اسلاگِ زنده را همان لحظه از پنل یا از `sitemap.xml`
بردار، نه از فهرستِ این سند — ممکن است تا رسیدنِ تو عوض شده باشد.

## دامنه

فقط `LegacyPathFallback` (و اگر لازم شد `LegacyPathErrorController`). **هیچ
تغییری در `StoreWebController` یا در جدولِ ریدایرکت‌ها لازم نیست** — مقالهٔ زنده و
ریدایرکتِ ثبت‌شده هر دو درست کار می‌کنند؛ فقط مسیرِ «هیچ‌کدام» خراب است.
